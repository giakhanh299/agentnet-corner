WEB vs yt-dlp TRÊN VPS (YouTube chạy được qua android client, TikTok chạy được):
So sánh — cài đặt: web không cần, yt-dlp cần setup ban đầu; dùng tay: web rất tiện,
yt-dlp cần dòng lệnh hoặc tự làm giao diện; tải hàng loạt: web thường bất tiện/có
thể bị giới hạn, yt-dlp rất phù hợp; chọn chất lượng: web phụ thuộc tùy chọn của
nó, yt-dlp kiểm soát trực tiếp hơn; metadata: web thường hạn chế, yt-dlp tốt;
thumbnail: web khác nhau, yt-dlp hỗ trợ; tự động hóa: web khó hơn/có thể cần API,
yt-dlp phù hợp; log/xử lý lỗi: web thường ít thông tin, yt-dlp chi tiết; bảo mật:
web phụ thuộc bên thứ ba, yt-dlp tự kiểm soát hơn; YouTube: web có thể chạm giới
hạn, yt-dlp đã chạy trong setup này; TikTok: nhiều lựa chọn web không watermark,
yt-dlp đã chạy; Facebook share/p: cả hai đều không đảm bảo; chi phí: nhiều web
miễn phí, yt-dlp là phần mềm miễn phí dùng tài nguyên VPS sẵn có. Dùng web khi:
chỉ cần một hoặc vài video; làm trên PC/điện thoại; không muốn vào VPS cho một
file; yt-dlp tạm lỗi trên một URL mà web xử lý được nguồn công khai đó; hoặc so
sánh chất lượng giữa các cách (vd Reel Facebook mà FSave tải ngay thì không cần
vòng qua VPS). Dùng yt-dlp khi: cần 30+ video; metadata phải đồng bộ với danh sách
nghiên cứu; cần log, retry tự động và tránh trùng lặp; file phải chảy tự động vào
FFmpeg, Whisper.cpp và công cụ phân tích khác; hoặc không muốn gửi danh sách URL
nghiên cứu cho nhiều web bên ngoài. Kết luận: giữ yt-dlp làm công cụ chính, web
làm dự phòng. Ghi chú pháp lý từ ChatGPT: điều khoản YouTube hạn chế tải hoặc tái
sử dụng nội dung ngoài trường hợp dịch vụ cho phép, chủ sở hữu quyền cho phép,
hoặc pháp luật cho phép; tải về để nghiên cứu không tự động cho phép tái sử dụng
footage, nhạc hay hình ảnh trong video thương mại.
